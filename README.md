# LLM Limits Overlay

**LLM Limits Overlay** — компактный Always-on-Top HUD-оверлей для Windows 10/11 с воздушной полупрозрачностью (~49%), монохромными индикаторами расхода и ClearType-текстом. Отображает в реальном времени текущие квоты и лимиты популярных нейросетевых моделей: **Gemini**, **Claude / GPT**, **Kimi** и **OpenRouter** в едином минималистичном плавающем окне.

## Возможности

- **Always-on-Top HUD**: парит над всеми окнами в правом нижнем углу экрана над панелью задач.
- **Динамическая автоподгонка высоты (`SizeToContent="Height"`)**: окно автоматически принимает высоту содержимого, а нижние скругления и тень карточек никогда не обрезаются.
- **Без лишних окон и значков**:
  - `ShowInTaskbar="False"`: не занимает место на панели задач Windows.
  - `WS_EX_TOOLWINDOW`: исключен из переключателя окон `Alt-Tab`.
  - Запуск через VBScript (`run_overlay.vbs`) скрытно стартует фоновый процесс — **никаких мигающих окон консоли PowerShell/CMD**.
- **Монохромная индикация**: единая шкала графитового оттенка, плавно темнеющая по мере расхода квоты от нейтрального серого к глубокому черному (без раздражающих светофорных цветов).
- **Свободное перемещение и контекстное меню**:
  - Левый клик: перетаскивание окна в любую удобную часть экрана.
  - Правый клик: стандартное контекстное меню с возможностью принудительного обновления квот и закрытия оверлея.
- **Асинхронный опрос и защита от зависаний**: обновление данных выполняется в фоне через WSL с жестким тайм-аутом 6 секунд и сторожевым таймером (watchdog), интерфейс всегда остается отзывчивым.

## Что отображает оверлей

Оверлей скомпонован сверху вниз тремя логическими блоками:

1. **KIMI** (верхняя карточка):
   - **Недельный лимит (7d)**: таймер до сброса квоты (например, `3д 8ч`), процент расхода (`100%`) и полоса прогресса.
   - **5-часовой лимит (5h)**: таймер до сброса (`2ч 41м`), процент расхода (`8.9%`) и шкала.
   - **Метка времени**: в правом нижнем углу карточки мелким нейтральным шрифтом отображается относительное время последнего обновления (`только что`, `4 мин`, `stale`), обновляемое каждые 10 секунд.
   - Источник: официальный эндпоинт `GET https://api.kimi.com/coding/v1/usages`.

2. **OPENROUTER** (средняя карточка):
   - **Лимит ключа / аккаунта**: таймер до расчетного сброса (`2д 13ч`), процент расхода (`3.7%`) и полоса прогресса.
   - **Служебная строка**: количество использованных бесплатных запросов (`free: 0/1000`) и остаток кредитного баланса (`ост. $9.63`).
   - Источник: `GET https://openrouter.ai/api/v1/key`.

3. **GEMINI + CLAUDE / GPT** (нижняя объединенная карточка):
   - Модели объединены в одну карточку с деликатным тонким разделителем:
     - **GEMINI**: недельное окно (7d, сверху) и 5-часовое окно (5h, снизу).
     - **CLAUDE / GPT**: недельное окно (7d, сверху) и 5-часовое окно (5h, снизу).
   - Источник: Language Server сессии Antigravity CLI через Connect RPC (`RetrieveUserQuotaSummary`).

## Системные требования

- **ОС**: Windows 10 или Windows 11 (64-bit).
- **PowerShell**: 5.1 или новее (входит в состав Windows).
- **WSL 2**: дистрибутив Linux (по умолчанию `Ubuntu-22.04` или любой настроенный) с установленным `python3`.

## Установка и настройка

### 1. Клонирование репозитория

Склонируйте проект в любую удобную папку на Windows:

```bash
git clone https://github.com/username/llm-limits-overlay.git
cd llm-limits-overlay
```

### 2. Настройка API-ключей

Для отображения лимитов OpenRouter и Kimi скрипту требуются соответствующие API-ключи. Скрипт автоматически ищет ключи в следующих местах:
1. Переменные окружения Windows / WSL: `OPENROUTER_API_KEY`, `KIMI_API_KEY`.
2. Файл `.env` в папке проекта.
3. Файл `~/.hermes/.env` в домашней директории WSL (если используется Hermes CLI).

#### Как получить ключи:
- **OpenRouter**: перейдите в [OpenRouter Keys](https://openrouter.ai/keys), создайте ключ с правами на чтение и сохраните его в `OPENROUTER_API_KEY`.
- **Kimi (Moonshot)**: перейдите в консоль разработчика [Kimi Open Platform](https://platform.moonshot.cn/) или в личный кабинет Kimi Coding, сгенерируйте API-токен и укажите его в `KIMI_API_KEY`.

Пример файла `.env` в корне проекта:
```env
OPENROUTER_API_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxx
KIMI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

*(Ключи никогда не выводятся в интерфейсе, не записываются в лог и не попадают в кэш-файлы)*

## Запуск

### Способ 1: Бесшумный запуск (Рекомендуемый)

Просто дважды щелкните по файлу:
```
run_overlay.vbs
```
Скрипт стартует через Windows Script Host (`wscript.exe`) с флагом `SW_HIDE (0)`. На экране **не появится ни одного окна консоли CMD или PowerShell**.

### Способ 2: Запуск через батник

Двойной клик по:
```
run_overlay.bat
```
Файл автоматически делегирует запуск в `run_overlay.vbs`.

## Конфигурация ($Config)

В начале скрипта `limits_overlay.ps1` расположен блок хэш-таблицы `$Config`, позволяющий быстро настроить визуальный стиль оверлея без редактирования XAML-разметки:

```powershell
$Config = @{
    # Прозрачность подложек карточек (~49% непрозрачности)
    PodBackground      = "#7CEEF2F6"  
    PodBorderBrush     = "#2064748B"  # Тонкая рамка (~12% непрозрачности)
    PodBorderThickness = 1.0          # Толщина границы (px)
    PodCornerRadius    = 8            # Скругление углов карточек

    # Цвета заголовков и текста
    GeminiHeader       = "#000000"    # Заголовок 'GEMINI'
    ClaudeHeader       = "#000000"    # Заголовок 'CLAUDE/GPT'
    OpenRouterHeader   = "#000000"    # Заголовок 'OPENROUTER'
    KimiHeader         = "#000000"    # Заголовок 'KIMI'
    LabelText          = "#0F172A"    # Подписи таймеров ('3ч 47м', '5д 23ч')
    MetaText           = "#0F172A"    # Служебные надписи и метка обновления

    # Заполнение полосы прогресса (монохромный темнеющий графит)
    ProgressFillStart  = "#4B5563"    # Оттенок при 0% расхода (Gray 600)
    ProgressFillEnd    = "#111827"    # Оттенок при 100% расхода (Gray 900)
    PercentText        = "#0F172A"    # Цвет процентов (Slate 900)
    PercentText100     = "#000000"    # Цвет процентов при 100% расходе
}
```

### Переменные окружения для путей и WSL

- `LLM_LIMITS_WSL_DISTRO` / `AGY_WSL_DISTRO`: имя дистрибутива WSL (по умолчанию `Ubuntu-22.04`).
- `LLM_LIMITS_WSL_SCRIPT` / `AGY_WSL_SCRIPT`: явный путь к `fetch_quota.py` внутри WSL (если скрипт лежит вне домашней папки).
- `LLM_LIMITS_JSON` / `AGY_LIMITS_JSON`: путь для выгрузки кэша JSON.
- `HERMES_ENV_PATH`: пользовательский путь к `.env`-файлу с ключами.

## Диагностика и логи

Все события запуска, завершения старых копий, циклы опроса и ошибки автоматически записываются в файл `overlay.log` рядом со скриптом:

```
[2026-10-23 15:41:03] === LLM Limits Overlay Starting (PID=892) ===
[2026-10-23 15:41:03] Cache loaded successfully from ...\limits.json (status: online).
[2026-10-23 15:41:03] Starting async fetch via wsl.exe (Ubuntu-22.04)...
[2026-10-23 15:41:05] Async refresh process finished (exitCode=0).
```

Если данные устарели (например, ПК вышел из спящего режима или Language Server был перезапущен), в статусе отображается `(stale)` до завершения следующего цикла опроса.
