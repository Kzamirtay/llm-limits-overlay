# LLM Limits Overlay — C# (.NET Framework 4.8 / WPF) Port

Нативный порт LLM Limits Overlay с PowerShell на C# под Windows 10/11. Оверлей отображает квоты моделей Gemini, Claude/GPT, Kimi и OpenRouter в компактном полупрозрачном HUD-окне над панелью задач с поддержкой режима «клики насквозь» и управления из системного трея.

---

## Архитектура и выбор стека

1. **Компилятор**: `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (.NET Framework 4.8).
   - Присутствует «из коробки» в любой стандартной установке Windows 10 и Windows 11.
   - Не требует установки .NET SDK, Visual Studio, MSBuild или внешних NuGet-пакетов.
2. **Интерфейс (WPF в чистом C# коде)**:
   - Интерфейс сконструирован программно без XAML-файлов и без markup compilation (который недоступен через автономный `csc.exe`).
   - Типобезопасная сборка дерева визуальных элементов (`Grid`, `Border`, `StackPanel`, `ProgressBar`, `TextBlock`).
   - Стилизованные прогресс-бары с плавной градиентной шкалой расхода (Gray 600 `#4B5563` → Gray 900 `#111827`) и скруглением 2.5px.
3. **Размер и производительность**:
   - Единый автономный исполняемый файл `LlmLimitsOverlay.exe` размером ~99 КБ со встроенной Win32-иконкой (`assets/app.ico`).
   - Подсистема Windows GUI (`/target:winexe`): запускается бесшумно, без мерцания консольных окон (в отличие от PowerShell, которому требовались скрипты `run_overlay.vbs`/`run_overlay.bat`).
4. **JSON-парсер без внешних зависимостей**:
   - Встроенный легковесный `SimpleJson` парсит `limits.json` и сериализует `overlay.config.json` без использования тяжеловесных или отсутствующих сборок.

## Как собрать проект

Для сборки достаточно запустить командный файл `build.cmd`:

```cmd
dotnet\build.cmd
```

или из корневого каталога:

```cmd
cmd /c "dotnet\build.cmd"
```

Скрипт компилирует все исходники `dotnet\LlmLimitsOverlay\*.cs` через `csc.exe` и сохраняет исполняемый файл в каталоге артефактов сборки:
`dotnet\bin\LlmLimitsOverlay.exe`

---

## Запуск приложения

Запуск нативного exe:

```cmd
.\dotnet\bin\LlmLimitsOverlay.exe
```

Приложение автоматически находит файлы проекта (`fetch_quota.py`, `overlay.config.json`, `limits.json`, `overlay.log`, `assets\app.ico`), поднимаясь вверх по дереву каталогов к корню репозитория.

### Специальные ключи запуска:
- `-DumpModel` — выводит текущее состояние модели и распарсенных квот в формате JSON в консоль и завершает работу.
- `-VerifyPosition` — выводит геометрические координаты окна и рабочей области в формате JSON и завершает работу.

## Паритет функций с PowerShell-версией

| Функция | PowerShell (`limits_overlay.ps1`) | C# (`LlmLimitsOverlay.exe`) |
|---|---|---|
| **HUD-окно WPF** | ~49% прозрачность, 3 карточки, без рамки, Always-on-Top, `WS_EX_TOOLWINDOW` (скрыт из Alt-Tab) | Полный паритет (нативный WPF C#) |
| **Позиционирование** | Правый нижний угол над панелью задач (`MarginRight=14`, `MarginBottom=4`) | Полный паритет (`SystemParameters.WorkArea`) |
| **Блоки данных** | KIMI (7d + 5h), OPENROUTER, GEMINI + CLAUDE/GPT (7d + 5h) | Полный паритет |
| **Клики насквозь (Click-Through)** | `WS_EX_TRANSPARENT + WS_EX_LAYERED`, включён по умолчанию | Полный паритет (`GWL_EXSTYLE = 0x000801A8`) |
| **Глобальный хоткей** | `Ctrl+Alt+L` (`RegisterHotKey` + `WM_HOTKEY`) | Полный паритет |
| **Системный трей** | `assets/app.ico`, меню: Показать/Скрыть, Обновить, Окружение, Клики насквозь, Сброс позиции, Выход | Полный паритет (`System.Windows.Forms.NotifyIcon`) |
| **Подсказка в трее** | Сводка квот (`Kimi 7д 100% · Gemini 90% · Claude 100% [сквозь]`) | Полный паритет |
| **Конфигурация** | `overlay.config.json` (backend, pythonPath, wslDistro, timeoutSeconds, testHooks, clickThrough, clickThroughHotkey) | Полный паритет, обратная совместимость |
| **Бэкенды опроса** | `windows` (нативный Python), `wsl` (WSL distros), `auto` (native → WSL fallback) | Полный паритет |
| **Асинхронный опрос & Watchdog** | 6 с (native) / 30 с (WSL), watchdog убивает зависший процесс и ставит метку `stale` | Полный паритет |
| **Один экземпляр** | Новый процесс заменяет старый из той же папки, закрывает старое окно без фантомных иконок | Полный паритет |
| **Формат логов** | `[YYYY-MM-DD HH:mm:ss] сообщение` в `overlay.log` | Полный паритет |
| **Тестовые хуки (.tray-action)** | Очередь команд при `testHooks: true` в конфиге | Полный паритет |

## Преимущества C# версии над PowerShell

1. **Мгновенный старт и отсутствие консольного окна**:
   - PowerShell-скрипту требовался запуск через `wscript.exe` + `run_overlay.vbs` со стилем окна `Hidden`, что вызывало кратковременные задержки и накладные расходы интерпретатора PowerShell.
   - C# EXE скомпилирован с флагом `/target:winexe` и стартует мгновенно как нативный процесс Windows.
2. **Минимальное потребление памяти**:
   - Размер бинарника всего ~99 КБ (PowerShell загружал `powershell.exe` ~60-90 МБ памяти вместе со средой скриптинга).
3. **Надёжность горячих клавиш и трея**:
   - Оконная процедура `HwndSourceHook` обрабатывает сообщения Windows напрямую в цикле сообщений WPF без задержек конвейера PowerShell.
4. **Стабильный жизненный цикл одного экземпляра**:
   - Корректная посылка `WM_CLOSE` старому экземпляру позволяет ему освободить ресурсы трея (`NotifyIcon.Dispose()`) и снять регистрацию глобального хоткея без появления «иконок-призраков».

## Известные ограничения

- Язык исходного кода ограничен C# 5 (так как компилятор .NET Framework 4.8 `csc.exe` не поддерживает синтаксис C# 6+ вроде интерполяции строк `$"..."`, свойств с телом-выражением `=>` и оператора `?.`). Код написан строго по спецификации C# 5 для гарантии компиляции на любой «чистой» Windows 10/11 без установки сторонних SDK.
- Для опроса квот по-прежнему требуется наличие Python (нативного Windows Python 3 или дистрибутива WSL с `python3`), так как бизнес-логика извлечения токенов и взаимодействия с API реализована в сопутствующем скрипте `fetch_quota.py`.
