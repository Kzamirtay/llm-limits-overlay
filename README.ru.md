# LLM Limits Overlay

[English](README.md) | **Русский**

**LLM Limits Overlay** — компактный Always-on-Top HUD-оверлей для Windows 10/11 с воздушной полупрозрачностью (~49%), монохромными индикаторами расхода и ClearType-текстом. Отображает в реальном времени текущие квоты и лимиты популярных нейросетевых моделей: **Gemini**, **Claude / GPT**, **Kimi** и **OpenRouter** в едином минималистичном плавающем окне.

## Возможности

- **Always-on-Top HUD**: парит над всеми окнами в правом нижнем углу экрана над панелью задач.
- **Динамическая автоподгонка высоты (`SizeToContent="Height"`)**: окно автоматически принимает высоту содержимого, а нижние скругления и тень карточек никогда не обрезаются.
- **Без лишних окон и значков**:
  - `ShowInTaskbar="False"`: не занимает место на панели задач Windows.
  - `WS_EX_TOOLWINDOW`: исключен из переключателя окон `Alt-Tab`.
  - Нативное Win32 GUI-приложение (`/target:winexe`) — **никаких мигающих окон консоли CMD или лончеров**.
- **Монохромная индикация**: единая шкала графитового оттенка, плавно темнеющая по мере расхода квоты от нейтрального серого к глубокому черному (без раздражающих светофорных цветов).
- **Свободное перемещение и управление из трея**:
  - Левый клик по окну: перетаскивание окна в любую удобную часть экрана.
  - Правый клик по окну: контекстное меню для принудительного обновления квот и закрытия оверлея.
  - Иконка в системном трее Windows: показ/скрытие окна в один клик, полное меню управления, сброс позиции и статусная подсказка с процентами.
- **Нативный опрос без внешних процессов (v1.2.0+, Python и WSL не нужны)**:
  - Все запросы к провайдерам выполняются **внутри процесса** `LlmLimitsOverlay.exe` в параллельных async-задачах — никаких subprocess, `wsl.exe` или Python.
  - Индивидуальные таймауты: HTTP 3.5 с для OpenRouter / Kimi; 8 с для `agy.exe`.
  - Кэширование квот Antigravity (300 с в `%TEMP%\llm_limits_agy_usage_cache.json`) сводит вызовы `agy.exe` к минимуму, сохраняя актуальность OpenRouter и Kimi на каждом 60-секундном тике.
- **Per-card время обновления (v1.2.0+)**:
  - Каждая из трёх карточек (KIMI / OPENROUTER / GEMINI+CLAUDE-GPT) показывает собственный возраст данных (`только что`, `N мин`) в правом нижнем углу.
  - Провайдеры обновляются независимо, поэтому возраст на карточках может различаться; упавший провайдер сохраняет время **последнего успешного фетча** и получает суффикс ` (stale)` только на своей карточке.

## Что отображает оверлей

Оверлей скомпонован сверху вниз тремя логическими блоками:

1. **KIMI** (верхняя карточка):
   - **Недельный лимит (7d)**: таймер до сброса квоты (например, `3д 8ч`), процент расхода (`100%`) и полоса прогресса.
   - **5-часовой лимит (5h)**: таймер до сброса (`2ч 41м`), процент расхода (`8.9%`) и шкала.
   - Источник: `GET https://api.kimi.com/coding/v1/usages` (HTTP Bearer-авторизация).

2. **OPENROUTER** (средняя карточка):
   - **Лимит ключа / аккаунта**: таймер до расчетного сброса (`2д 13ч`), процент расхода (`3.7%`) и полоса прогресса.
   - **Служебная строка**: количество использованных бесплатных запросов (`free: 0/1000`) и остаток кредитного баланса (`ост. $9.63`).
   - Источник: `GET https://openrouter.ai/api/v1/key` (HTTP Bearer-авторизация).

3. **GEMINI + CLAUDE / GPT** (нижняя объединенная карточка):
   - Модели объединены в одну карточку с деликатным тонким разделителем:
     - **GEMINI**: недельное окно (7d, сверху) и 5-часовое окно (5h, снизу).
     - **CLAUDE / GPT**: недельное окно (7d, сверху) и 5-часовое окно (5h, снизу).
   - Источник: нативный `agy.exe -p /usage --output-format json` (Antigravity CLI v1.4.9+).

Каждая карточка показывает собственное **относительное время обновления** в правом нижнем углу (`только что`, `N мин`); оно пересчитывается каждые 10 секунд UI-таймером — без сетевых запросов. Если блок провайдера в статусе `stale`, суффикс ` (stale)` получает только его карточка, а таймстемп продолжает показывать время **последнего успешного фетча** и стареет дальше, так что виден реальный возраст отображаемых данных. Глобальная пометка stale сразу на всех карточках появляется только когда весь снимок не в статусе `online` (например, самый первый запуск без файла кэша). Формулировки и формат строк — константы в `OverlayTheme.cs` (`RelativeTimeJustNow`, `RelativeTimeStaleSuffix` и т.д.).

## Системные требования

- **ОС**: Windows 10 или Windows 11 (64-bit) с .NET Framework 4.8 (входит в состав Windows).
- **Antigravity CLI**: `agy.exe` (v1.4.9+), установлен и авторизован (`agy auth login`). Находится автоматически из `PATH` или `%LOCALAPPDATA%\agy\bin\agy.exe`.
- **Python не нужен. WSL не нужен.** Начиная с v1.2.0 оверлей полностью самодостаточен.

## Архитектура (v1.2.0+)

### Внутрипроцессный фетч

С версии v1.2.0 все запросы квот выполняются **внутри `LlmLimitsOverlay.exe`** без внешних процессов или скриптов:

| Провайдер | Транспорт | Таймаут | Авторизация |
|---|---|---|---|
| OpenRouter | `HttpWebRequest GET https://openrouter.ai/api/v1/key` | 3.5 с | Bearer `OPENROUTER_API_KEY` из `.env` |
| Kimi | `HttpWebRequest GET https://api.kimi.com/coding/v1/usages` | 3.5 с | Bearer `KIMI_API_KEY` из `.env` |
| AGY (Gemini/Claude) | `Process.Start(agy.exe -p /usage --output-format json)` | 8 с | OAuth-токен проверяется заранее по `%USERPROFILE%\.gemini\antigravity-cli\antigravity-oauth-token` |

Все три провайдера запускаются параллельно через `Task.Run`. По готовности каждый атомарно записывает свой фрагмент (`limits.agy.json`, `limits.openrouter.json`, `limits.kimi.json`), после чего собирается итоговый `limits.json`. Падение одного провайдера не блокирует остальных.

### Защита от OAuth-попапа

Перед запуском `agy.exe` оверлей проверяет наличие и непустоту файла `%USERPROFILE%\.gemini\antigravity-cli\antigravity-oauth-token`. Если токен отсутствует — `agy.exe` не запускается совсем (возвращается `stale`), без открытия браузера.

### Кэш AGY

Сырой JSON-ответ `agy.exe` кэшируется на 300 секунд в `%TEMP%\llm_limits_agy_usage_cache.json`. В течение TTL `agy.exe` повторно не запускается; кэш переживает рестарт процесса.

### Изоляция ошибок

Если `agy.exe` зависает или не найден — только карточка Gemini/Claude показывает `stale`; OpenRouter и Kimi продолжают обновляться в штатном режиме. Общий статус `limits.json` остаётся `online`, если доступен хотя бы один провайдер.

### Формат `limits.json`

Начиная с коммита `4f7df9a` (per-card время обновления) каждый блок провайдера несёт **собственный** `last_updated` — время последнего успешного фетча этого провайдера (`yyyy-MM-dd HH:mm:ss`, локальное время). Корневой объект:

```json
{
  "status": "online",
  "last_updated": "2026-10-28 16:38:27",
  "data": {
    "gemini_5h":     { "percent": 88.0, "fraction": 0.8802, "used_percent": 12.0, "used_fraction": 0.1198, "reset_in": "2h 40m", ... },
    "gemini_weekly": { ... },
    "claude_5h":     { ... },
    "claude_weekly": { ... },
    "agy":        { "status": "online", "last_updated": "2026-10-28 16:38:27" },
    "openrouter": { "status": "online", "last_updated": "2026-10-28 16:38:27", "limit": 10.0, "usage": 1.36, "limit_remaining": 9.51, ... },
    "kimi": {
      "status": "online",
      "last_updated": "2026-10-28 16:38:27",
      "limit_5h": { "used_ratio": 0.39, "used_percent": 39.3, "reset_in": "1h 43m", ... },
      "limit_7d": { ... }
    }
  }
}
```

Семантика таймстемпов:

- `data.agy` — мета-блок всей карточки Gemini+Claude/GPT (сами значения бакетов по-прежнему лежат в `gemini_5h`, `gemini_weekly`, `claude_5h`, `claude_weekly`).
- При ошибке или таймауте блок провайдера становится `stale`, а его `last_updated` **сохраняется от последнего успеха** — он продолжает стареть, и UI показывает реальный возраст отображаемых данных.
- Cache-hit agy **не сдвигает** таймстемп: он берётся из записи кэша, поэтому карточка отражает возраст кэшированных данных (до 300 с).
- Корневой `last_updated` — время последнего мержа всех трёх провайдеров; корневой `status` остаётся `online`, пока доступен хотя бы один провайдер.
- Если per-provider `last_updated` отсутствует (файл записан старой версией), при чтении используется корневой `last_updated`.

## Иконка в трее

Оверлей снабжен значком в системной области уведомлений (Windows System Tray), позволяющим полноценно контролировать HUD даже тогда, когда само окно скрыто или перекрыто другими полноэкранными приложениями.

### Действия с иконкой
- **Клик или двойной клик левой кнопкой мыши**: мгновенно скрывает или возвращает окно оверлея на экран (положение окна при скрытии и повторном показе полностью сохраняется).
- **Всплывающая подсказка (Tooltip)**: при наведении курсора на значок выводится компактная сводка текущих лимитов в одну строку (например: `Kimi 7д 100% · Gemini 47% · Claude 50%`), обновляемая автоматически при каждой перезагрузке данных.

### Контекстное меню трея (правый клик)
- **«Показать оверлей» / «Скрыть оверлей»** — переключает видимость окна с сохранением его текущих координат.
- *Разделитель*
- **«Обновить квоты»** — принудительный немедленный опрос API (блокируется на время выполнения фонового запроса).
- **«Клики насквозь»** — переключатель режима прозрачности оверлея для мыши (с отметкой состояния).
- *Разделитель*
- **«Сбросить позицию»** — возвращает перемещенный оверлей в исходное положение в правом нижнем углу экрана над панелью задач.
- **«Выход»** — корректно удаляет иконку из трея, закрывает окно и завершает процесс.

> [!NOTE]
> **Windows 11**: новые значки приложений операционная система по умолчанию помещает в область скрытых значков (переполнение / overflow, кнопка со стрелкой `^`). Чтобы иконка отображалась в трее постоянно:
> перейдите в **Параметры → Персонализация → Панель задач → «Другие значки в трее»** и включите переключатель для оверлея, либо просто перетащите значок мышью из окна `^` на основную панель задач.

## Режим «клики насквозь»

Оверлей поддерживает специальный режим **«клики насквозь» (click-through mode)**, который **включен по умолчанию**.

В этом режиме:
- Окно оверлея абсолютно прозрачно для мыши на уровне Win32 (`WS_EX_TRANSPARENT`).
- Любые действия мыши — левые и правые клики, двойные клики, прокрутка колесика и наведение курсора — беспрепятственно проходят в окна и элементы управления, расположенные под оверлеем.
- Окно оверлея **нельзя перетаскивать мышью**, и по нему **не открывается контекстное меню правого клика**.
- Сам оверлей визуально отображается поверх всех окон, не мешая работе с окнами под ним. Позиция окна по умолчанию фиксируется в правом нижнем углу над панелью задач, а сбросить или вернуть её можно через пункт трея **«Сбросить позицию»**.

### Как выключить или переключить режим
Если вам требуется интерактивное взаимодействие с окном (перетаскивание или вызов его контекстного меню), режим можно временно или постоянно отключить:
1. **Глобальная горячая клавиша**: комбинация **`Ctrl+Alt+L`** (работает глобально из любого приложения). Первое нажатие моментально выключает режим и возвращает интерактивность окну, повторное — снова включает сквозные клики.
2. **Контекстное меню трея**: правый клик по значку в системном трее → пункт **«Клики насквозь»** (снять галочку).
3. **Файл конфигурации**: установить `"clickThrough": false` в `overlay.config.json`, чтобы оверлей запускался в стандартном интерактивном режиме.

При каждом переключении в системном трее выводится информационное уведомление (balloon tip), а во всплывающей подсказке к иконке отображается статус `[сквозь]` (когда режим активен). Выбранное состояние автоматически сохраняется в `overlay.config.json` и восстанавливается при следующем запуске.

> [!WARNING]
> **Ограничения режима**: когда включен режим «клики насквозь», клики по самому окну оверлея не регистрируются приложением.
> **Значок в системном трее и глобальная комбинация клавиш (`Ctrl+Alt+L`) — единственные способы вернуть интерактивное взаимодействие.**

## Конфигурация

### Файл `overlay.config.json`

Файл конфигурации создается автоматически рядом с исполняемым файлом:

```json
{
  "backend": "native",
  "timeoutSeconds": 0,
  "testHooks": false,
  "clickThrough": true,
  "clickThroughHotkey": "Ctrl+Alt+L"
}
```

- `backend`: всегда `"native"` начиная с v1.2.0 (Python/WSL удалены). Устаревшие значения `auto`/`windows`/`wsl` молча нормализуются.
- `timeoutSeconds`: общий бюджет фетча в секундах (0 = по умолчанию 10 с).
- `testHooks`: включение тестовых хуков через управляющий файл `.tray-action` (по умолчанию `false`, выключено).
- `clickThrough`: режим «клики насквозь» при запуске оверлея (по умолчанию `true`, включено). Задайте `false`, если требуется запуск в интерактивном режиме.
- `clickThroughHotkey`: глобальная комбинация клавиш для быстрого переключения режима (по умолчанию `"Ctrl+Alt+L"`, поддерживает модификаторы Ctrl, Alt, Shift, Win и клавиши).

### Переменные окружения

- `LLM_LIMITS_AGY_BIN`: явный путь к `agy.exe`.
- `LLM_LIMITS_QUOTA_CACHE_SECONDS`: время кэширования квот Antigravity (по умолчанию `300`).
- `LLM_LIMITS_JSON` / `AGY_LIMITS_JSON`: путь для выгрузки результирующего кэша JSON.

## Настройка API-ключей

Для отображения лимитов OpenRouter и Kimi приложению требуются соответствующие API-ключи.

### Порядок загрузки ключей
API-ключи читаются из файла `.env`, расположенного **рядом с `LlmLimitsOverlay.exe`** (приоритет), с fallback на переменные окружения процесса.

> [!IMPORTANT]
> Ключи **никогда** не записываются в `overlay.log`, `limits.json` или файлы кэша.
> OpenRouter возвращает сам ключ в поле `label`, если у ключа нет имени — оверлей распознаёт похожие на ключ значения и сохраняет их в замаскированном виде (`sk-or-...XXXX`), так что сырые ключи на диск не попадают.

### Пример файла `.env`
Шаблон доступен в репозитории в файле [.env.example](.env.example):

```env
# LLM Limits Overlay - Конфигурация API-ключей
OPENROUTER_API_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxx
KIMI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Встроенный C#-парсер поддерживает:
- UTF-8 BOM и стандартный UTF-8;
- переводы строк CRLF (Windows) и LF (Linux);
- пустые строки и комментарии, начинающиеся с `#`;
- опциональный префикс `export `;
- пробелы вокруг знака равенства (`KEY = value`);
- одинарные и двойные кавычки вокруг значений (`'...'` / `"..."`);
- замыкающие инлайн-комментарии после значений вне кавычек (`KEY=value # комментарий`);
- пропуск некорректных строк без вызова исключений.

*(Ключи никогда не выводятся в терминал/stdout/stderr, не отображаются в интерфейсе, не записываются в `overlay.log` и не сохраняются в файлы кэша `limits.json`)*.

## Установка и запуск

Единственный способ запуска оверлея — исполняемый файл **`LlmLimitsOverlay.exe`**.

> [!NOTE]
> **PowerShell-версия удалена из master; она доступна в теге/релизе [v1.0.0](https://github.com/Kzamirtay/llm-limits-overlay/releases/tag/v1.0.0).** Начиная с версии v1.1.0 оверлей работает исключительно как нативное C# GUI-приложение (.NET Framework 4.8 / WPF). С версии v1.2.0 Python и WSL больше не требуются.

### Требования к окружению для запуска
Рядом с `LlmLimitsOverlay.exe` должны лежать следующие файлы:
- `assets/app.ico` — иконка приложения для окна и системного трея;
- `overlay.config.json` — конфигурация (создаётся автоматически, если отсутствует);
- `.env` — файл API-ключей (`OPENROUTER_API_KEY`, `KIMI_API_KEY`).

### Способы запуска

#### 1. Запуск готового бинарника из Releases
1. Скачайте последний архив `LlmLimitsOverlay-vX.Y.Z-win64.zip` со страницы [Releases](https://github.com/Kzamirtay/llm-limits-overlay/releases).
2. Распакуйте в любую удобную папку.
3. Создайте `.env` с API-ключами (скопируйте из `.env.example`).
4. Убедитесь, что `agy.exe` установлен и вы авторизованы (`agy auth login`).
5. Запустите `LlmLimitsOverlay.exe` двойным кликом в проводнике Windows или из командной строки:
   ```cmd
   LlmLimitsOverlay.exe
   ```
   Приложение скомпилировано как подсистема Windows GUI (`/target:winexe`) и стартует бесшумно — без мигающих консольных окон CMD или вспомогательных лончеров.

#### 2. Сборка из исходников
Если вы клонировали репозиторий и хотите собрать бинарник самостоятельно:
```cmd
dotnet\build.cmd
```
Скрипт автоматически находит системный `csc.exe` (`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`), не требует установки Visual Studio, MSBuild или .NET SDK, и компилирует автономный бинарник в:
```
dotnet\bin\LlmLimitsOverlay.exe
```
Подробная техническая документация и архитектура порта описаны в [dotnet/README.md](dotnet/README.md).

#### 3. Windows-установщик (v1.2.0+)
Доступен per-user установщик: `LlmLimitsOverlay-Setup-1.2.1.exe` (Inno Setup 6).

**Возможности:**
- Устанавливается в `%LOCALAPPDATA%\LlmLimitsOverlay` — без запроса прав администратора (UAC).
- Ярлык в меню Пуск (всегда); опционально — ярлык на Рабочем столе и автозапуск (HKCU Run).
- Запись в «Приложения и компоненты» / «Программы и компоненты» для корректного удаления.
- **Ваш `.env` сохраняется** при обновлении и удалении (`onlyifdoesntexist`, `uninsneveruninstall`).
- Перед установкой/обновлением закрывает запущенный экземпляр оверлея из этой же папки.
- При удалении удаляются файлы данных (`limits*.json`, `overlay.log`); `.env` остаётся.

**Тихая установка (для автоматизации):**
```cmd
LlmLimitsOverlay-Setup-1.2.1.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG=%TEMP%\llmo-install.log
```
> [!NOTE]
> **Предупреждение SmartScreen**: установщик не подписан цифровой подписью (нет EV-сертификата). Windows SmartScreen покажет «Защита Windows» — нажмите «Подробнее» → «Всё равно запустить». Это нормально для open-source проектов без платного сертификата.

**Удаление:** через «Приложения и компоненты» в Параметрах Windows, или тихо:
```cmd
"%LOCALAPPDATA%\LlmLimitsOverlay\unins000.exe" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

#### 4. CLI: `llm-limits.exe`
Рядом с GUI поставляется консольная утилита (тот же движок фетча, те же таймауты и кэш). Выводит статус квот в терминал — удобно для скриптов и быстрых проверок.

```cmd
llm-limits.exe                 # выровненная таблица по трём провайдерам
llm-limits.exe --json         # машиночитаемый JSON (status + блоки провайдеров)
llm-limits.exe --provider kimi
llm-limits.exe --watch 30     # цикл обновления; выход — Ctrl+C
llm-limits.exe --no-cache     # игнорировать кэш agy /usage (форс-запуск agy.exe)
llm-limits.exe --env .env --agy-bin C:\tools\agy.exe
```

- `--provider kimi|openrouter|agy`, `--env <путь>`, `--config <путь>`, `--agy-bin <путь>` — переопределения.
- `--no-color` и переменная окружения `NO_COLOR` отключают ANSI-цвета.
- В режиме `--watch` при перенаправленном (не-TTY) выводе печатается блок за тик вместо перерисовки экрана.
- Коды выхода: `0` — все провайдеры online; `2` — часть stale/disabled; `1` — все недоступны или ошибка аргументов.
- API-ключи и сырые label OpenRouter не печатаются (label маскируется, как в `limits.json`).

## Диагностика и логи

Все события запуска, результаты опроса, кэш-хиты и возможные ошибки фиксируются в файле `overlay.log` рядом с исполняемым файлом:

```
[2026-10-28 15:30:00] === LLM Limits Overlay Starting (PID=12345) ===
[2026-10-28 15:30:00] Cache loaded successfully from ...\limits.json (status: online).
[2026-10-28 15:30:00] Starting async native refresh at 2026-10-28 15:30:00...
[2026-10-28 15:30:01] [cache] agy /usage cache hit (age 45.3s <= 300s), agy.exe not respawned
[2026-10-28 15:30:01] Native refresh finished (agy: online, openrouter: online, kimi: online -> root: online).
```

Строк `Spawned refresh process` и `exitCode` в логе нет — фетч внутрипроцессный.
